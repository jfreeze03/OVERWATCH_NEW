## What it fixes (metrics-triage HIGH #2)

`MART_TASK_GRAPH_DAILY.WH_CREDITS` (pipeline spend / $-per-run on Cost → Unit costs
→ Graphs) read ~$0 for every task whose body is a stored procedure. Arm [6] rolled
`QUERY_ATTRIBUTION_HISTORY` up by the **bare QUERY_ID** and joined
`a.QUERY_ID = h.QUERY_ID` — but a proc's compute lands on its CHILD statements,
which carry the task's `CALL` query id only as `ROOT_QUERY_ID`, so the bare-id join
matched only the ~0-credit CALL row.

The live twin (`app/data/graph_sql.graph_daily_costs`) was fixed for exactly this in
v4.60 (audit #10); the default-served mart never got it — so the mart under-reported
while the live fallback was correct. V059 re-derives arm [6] to mirror the live
builder: roll up by `COALESCE(ROOT_QUERY_ID, QUERY_ID)`, prune on the same coalesced
id, and join `a.ROOT_ID = h.QUERY_ID`.

## Correcting history

Forward loads self-correct on the next hourly cycle; the nightly reconcile repairs
the trailing days. To correct older `WH_CREDITS` in one pass, re-run the marts for a
wider window off-peak — `QUERY_ATTRIBUTION_HISTORY` retains ~365 days, so:

```sql
CALL DBA_MAINT_DB.OVERWATCH.SP_LOAD_MARTS_V27('HOURLY', 90);
```

(arm [6] is not window-capped, so it rebuilds the full requested span.)

## What it does / why

Codex r29 #1 (CONFIRMED regression in deployed V052): V052 added 180 and 365 to
the exec-board loader's `windows` CTE, but the three source CTEs
(`wh_daily`/`qh_daily`/`tk_daily`) still capped their reads at 90 days
(`WHERE DAY >= DATEADD('day', -90, CURRENT_DATE())`). The window join reads from
those already-capped frames, so the **180- and 365-day pills computed over only
90 days** — they rendered as distinct windows but held values identical to the
90-day row.

`snowflake/migrations/V054__exec_board_window_history.sql`:
- Re-derives `SP_REFRESH_EXEC_BOARD` (from V052) — the three source horizons
  `-90 → -365` (= max `DAY_WINDOW_OPTIONS`). Sources are `FACT_*_DAILY` (mart,
  long retention), so this is history, not a live rescan; the
  aggregate-once/join-small shape is unchanged.
- Re-derives `SP_PURGE_FACTS` (from V045) — daily-fact retention floor
  `180 → 365` so retained history always covers the max advertised window. Under
  the default `FACT_RETENTION_DAYS_DAILY = 800` this is a **runtime no-op**; it
  only tightens the guarantee (and makes the CI invariant enforceable
  end-to-end: read horizon AND retained history both ≥ max window).
- Re-`CALL`s `SP_REFRESH_EXEC_BOARD()` so the 180/365 pills carry real
  long-window data immediately.

Not included: Codex r29 #7 (QH watermark advance) — **already fixed** in V042
(codex_r22 #7); that reviewer cited the superseded V041 body. See the r29
adjudication doc.

## Verify

```sql
-- 1. Version: expect 54
SELECT MAX(VERSION) FROM DBA_MAINT_DB.OVERWATCH.SCHEMA_VERSION;

-- 2. The long windows now differ from the 90-day window (the bug was they were
--    identical). Expect the 365-day CREDITS row >= the 90-day row, and (once a
--    few days pass) strictly greater as older history accrues into the window.
SELECT WINDOW_DAYS, VALUE AS CREDITS, VALUE_USD
FROM DBA_MAINT_DB.OVERWATCH.MART_EXEC_BOARD
WHERE COMPANY = 'ALL' AND PANEL = 'KPI' AND METRIC = 'CREDITS'
  AND WINDOW_DAYS IN (90, 180, 365)
ORDER BY WINDOW_DAYS;

-- 3. Board holds rows for all seven windows (sanity — unchanged from V052):
SELECT DISTINCT WINDOW_DAYS FROM DBA_MAINT_DB.OVERWATCH.MART_EXEC_BOARD ORDER BY 1;
```

Note: how much larger 180/365 read than 90 depends on how much daily-fact
history the account actually holds (`backfill_365.sql` seeds a year; day facts
retain 800 by default). If only N < 365 days exist, the 365 window honestly
shows N days — that is correct, not a truncation. The bug was showing 90 when
more existed.

Then `snowflake/validate.sql` — top row reads `V001..V054 applied`.

## Rollback

Both procs are `CREATE OR REPLACE`; re-running V052's block reverts the board
horizons and re-running V045's block reverts the retention floor. Nothing is
dropped; no data is deleted (the floor change only *retains more*).

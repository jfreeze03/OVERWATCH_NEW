# Deploy runbook — V055 — 2026-07-28

One worksheet, Snowsight, off-peak. Prereq: V054 applied
(`SELECT MAX(VERSION) FROM DBA_MAINT_DB.OVERWATCH.SCHEMA_VERSION;` = 54).

Low-risk: one additive column + one new table/proc + two proc re-derivations +
one first-fill. **No new task, no task-graph change, no owner-privileged
free-text execution, no new QUERY_HISTORY scan.**

## What it does / why

The `COST_CLOUD_SVC_RATIO` alert sits >21% on two warehouses. The Spend page
already shows the ratio, the rebate, compile-heavy families, and CS-by-type —
but nothing names the exact query *shapes* and *users* burning the
cloud-services credits (a metadata storm of tiny SHOW/DESCRIBE queries never
surfaces in the compile-heavy view). V055 persists per-query cloud-services
credits so that drill-down is mart-backed (no live scan) and gains history.

`snowflake/migrations/V055__cloud_services_breakdown.sql`:
- `OW_QH_EXTRACT` gains `CREDITS_USED_CLOUD_SERVICES` (additive; the extract
  already scans `QUERY_HISTORY` once, so no new scan).
- `SP_LOAD_QH_EXTRACT` re-derived (from V042) to fill the column and cascade a
  **guarded, isolated** `CALL SP_LOAD_CLOUD_SVC_MART()` (its failure logs to
  `APP_ERROR_LOG` and never breaks the extract or the watermark).
- `MART_CLOUD_SVC_DAILY` — CS credits at day / company / warehouse / user /
  role / query_type / parameterized_hash grain, CS>0 only.
- `SP_LOAD_CLOUD_SVC_MART` — MERGEs the trailing 3 days from the extract.
- `SP_PURGE_FACTS` re-derived (from V054) to trim the new mart on the daily
  floor.

App (already committed, v4.57.0): Spend → "Cloud-services health by warehouse"
gains a **warehouse picker** and two mart-backed tables — top query shapes by CS
credits, and CS by user/role — for **any** warehouse (not only ELEVATED). The
alert-drawer recheck for `COST_CLOUD_SVC_RATIO` is now warehouse-scoped (matches
the per-warehouse alert instead of showing the account-wide ratio).

## Verify

Replace `WH_A` / `WH_B` with the two flagged warehouses (one is
`WH_TRXS_TRANSFORM` per the alert's CoCo note; fill in the second):

```sql
-- 1. Version: expect 55
SELECT MAX(VERSION) FROM DBA_MAINT_DB.OVERWATCH.SCHEMA_VERSION;

-- 2. Column present + populated on the extract (expect nonzero CS rows):
SELECT COUNT(*) AS rows_with_cs
FROM DBA_MAINT_DB.OVERWATCH.OW_QH_EXTRACT
WHERE CREDITS_USED_CLOUD_SERVICES > 0;

-- 3. The mart has the two warehouses' drivers (top shapes by CS credits):
SELECT WAREHOUSE_NAME, QUERY_TYPE, LEFT(SAMPLE_TEXT, 60) AS sample,
       SUM(RUNS) AS runs, ROUND(SUM(CS_CREDITS), 3) AS cs_credits
FROM DBA_MAINT_DB.OVERWATCH.MART_CLOUD_SVC_DAILY
WHERE WAREHOUSE_NAME IN ('WH_A', 'WH_B')
GROUP BY 1, 2, QUERY_PARAMETERIZED_HASH, SAMPLE_TEXT
ORDER BY cs_credits DESC
LIMIT 20;

-- 4. Who's driving it:
SELECT WAREHOUSE_NAME, USER_NAME, ROLE_NAME,
       SUM(RUNS) AS runs, ROUND(SUM(CS_CREDITS), 3) AS cs_credits
FROM DBA_MAINT_DB.OVERWATCH.MART_CLOUD_SVC_DAILY
WHERE WAREHOUSE_NAME IN ('WH_A', 'WH_B')
GROUP BY 1, 2, 3 ORDER BY cs_credits DESC LIMIT 20;
```

Then `snowflake/validate.sql` — top row reads `V001..V055 applied`. In the app:
Cost & Contract → Spend & Attribution → "Cloud-services health by warehouse" →
pick a warehouse and read the shape/user tables.

History note: the mart accumulates **forward** from deploy (the extract retains
~3 days). For CS history *before* deploy, use the Snowsight
`QUERY_HISTORY.CREDITS_USED_CLOUD_SERVICES` queries directly — the mart will
have full history after ~1 day of loading, 365-day retention thereafter.

## Rollback

The column is additive on a TRANSIENT table (harmless to leave). The mart +
loader are droppable (`snowflake/teardown.sql` lists both). Both re-derived
procs are `CREATE OR REPLACE` — re-run V042's `SP_LOAD_QH_EXTRACT` and V054's
`SP_PURGE_FACTS` blocks to revert. No data is deleted by this migration.

# Deploy runbook — V050 (2026-07-27)

One worksheet, run by Joe in Snowsight, off-peak. Prereq: V048/V049 applied
(done 2026-07-27 — `SELECT MAX(VERSION) FROM DBA_MAINT_DB.OVERWATCH.SCHEMA_VERSION;`
should read 49 before you start).

## What it does

`snowflake/migrations/V050__one_pass_read_write_arms.sql` — one proc swap:

- **One-pass loader**: QUERY_ATTRIBUTION_HISTORY aggregated once and
  ACCESS_HISTORY flattened once per array into session-scoped temp stages
  (V049 re-scanned QAH per insert and flattened AH four times). The daily
  06:45 task gets proportionally cheaper; the 14-day reload in this
  worksheet is the same weight as the V049 one you just ran, minus the
  duplicate scans.
- **Read/write arms**: every split share is labeled — `QUERY_COMPUTE_WRITE`
  (production: the cost of building the object) vs `QUERY_COMPUTE_READ`
  (consumption). Write wins when one query both reads and writes, so each
  object keeps ONE share and additivity holds.
- **Riding fix**: credits for queries whose only touched object has a NULL
  name used to vanish (V049's residual guard counted them attributed while
  the split had no row); they now land in `QUERY_COMPUTE_RESIDUAL`.

## Verify

```sql
-- 1. Version: expect 50
SELECT MAX(VERSION) FROM DBA_MAINT_DB.OVERWATCH.SCHEMA_VERSION;

-- 2. The new arms landed and partition the old one (recent days only —
--    days older than the 14d reload keep legacy QUERY_COMPUTE, by design)
SELECT COST_ARM, ROUND(SUM(CREDITS), 4) AS CREDITS, COUNT(*) AS ROWS_
FROM DBA_MAINT_DB.OVERWATCH.FACT_OBJECT_COST_DAILY
WHERE DAY >= DATEADD('day', -14, CURRENT_DATE())
GROUP BY 1 ORDER BY 2 DESC;
-- expect QUERY_COMPUTE_READ + QUERY_COMPUTE_WRITE rows, no QUERY_COMPUTE
-- inside the window; the WRITE share is your production/ETL build cost.

-- 3. The additive contract, checked end to end (also on Admin > Canary >
--    "Object-cost ledger reconciliation" in the app):
--    run the object_cost_recon query — DELTA ~0 on every row.
```

Then `snowflake/validate.sql` — top row reads `V001..V050 applied` — and the
app's Optimize page caption reads V048–V050.

## Caveats

- The read/write split only exists inside the reload window; run
  `CALL DBA_MAINT_DB.OVERWATCH.SP_LOAD_OBJECT_COST(30);` afterward if you
  want a full month re-labeled (one heavier scan, same idempotent delete+
  reload semantics).
- Temp stages (`OW_OBJCOST_*_STAGE`) are session-scoped — nothing new to
  tear down.

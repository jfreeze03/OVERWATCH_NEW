## What it fixes

- **#6 FACT_QUERY_DAILY partial-freeze** — `SP_LOAD_QH_EXTRACT`'s day-fact MERGE
  read a rolling 72h window and overwrote the oldest calendar day with a
  shrinking partial as the window slid off it, freezing every aging day at ~its
  last hour (~95% undercount) — which fed the exec-board query-volume windows.
  Now day-aligned (`-2 CURRENT_DATE`), so an aging day freezes complete.
- **#7 nightly-reconcile D-3 damage** — `SP_NIGHTLY_RECONCILE` deleted the
  query/extract-sourced day marts for `DAY >= -3d` then rebuilt them from the
  72h extract via `SP_LOAD_MARTS_V27('HOURLY', 3)`, so day D-3 rebuilt partial
  (~28% short) every night. Fix: the four **extract-fed** day arms of
  `SP_LOAD_MARTS_V27` cap at `LEAST(:d, 2)` (the extract holds at most 2 whole
  days complete; the normal hourly `d=2` call is unchanged), and the reconcile
  deletes those marts at `-2d`. The reconcile keeps `d=3`/`-3d` for the marts it
  can rebuild D-3 complete: the full-retention marts
  (`MART_WAREHOUSE_EFFICIENCY_DAILY`, `MART_TASK_GRAPH_DAILY`), the hour-grain
  marts, and the primary metering facts (`FACT_WAREHOUSE_DAILY`,
  `FACT_METERING_DAILY`) — the last being what the reconcile exists for.
- **#14 ops-diag hour double-count** — `SP_LOAD_OPS_DIAG` deleted on the
  hour-truncated `HOUR_TS` with a non-hour-aligned bound while re-inserting a
  partial bucket for the boundary hour, leaving a complete + partial row that the
  Operations panels double-counted. Both bounds now hour-aligned.
- **#4 PIPE_TASK_FAILURES dedupe** — key gains `SCHEMA_NAME` (same-named tasks in
  different schemas no longer collide and suppress each other).
- **#12 SEC_CRED_EXPIRY escalation** — dedupe key gains an EXPIRED/EXPIRING
  discriminator so the CRITICAL "expired" escalation is no longer deduped against
  the earlier same-week "expiring" warning.
- **#13 COST_CLOUD_SVC_RATIO company** — classified via `COMPANY_FOR_WAREHOUSE`
  (V044 evidence-based) instead of `WH_TRXS%` name pattern, so an UNKNOWN
  warehouse no longer bills ALFA on the alert.

## Verify

```sql
-- 1. Version: expect 56
SELECT MAX(VERSION) FROM DBA_MAINT_DB.OVERWATCH.SCHEMA_VERSION;

-- 2. Aging FACT_QUERY_DAILY days are now complete, not ~a single hour. After a
--    day passes, a day 3-5 days old should hold a full day's query count
--    comparable to its neighbors (not a ~5% sliver):
SELECT DAY, SUM(QUERY_COUNT) AS queries
FROM DBA_MAINT_DB.OVERWATCH.FACT_QUERY_DAILY
WHERE DAY >= DATEADD('day', -7, CURRENT_DATE())
GROUP BY DAY ORDER BY DAY;

-- 3. Ops-diag has no duplicate rows per (HOUR_TS, KIND, QUERY_ID):
SELECT HOUR_TS, KIND, QUERY_ID, COUNT(*) c
FROM DBA_MAINT_DB.OVERWATCH.MART_OPS_DIAG_HOURLY
WHERE KIND = 'TOP_ELAPSED' AND QUERY_ID IS NOT NULL
GROUP BY 1,2,3 HAVING COUNT(*) > 1 LIMIT 10;   -- expect zero rows
```

# Deploy runbook — V051 (2026-07-27)

One worksheet, run by Joe in Snowsight, off-peak. Prereq: V050 applied
(`SELECT MAX(VERSION) FROM DBA_MAINT_DB.OVERWATCH.SCHEMA_VERSION;` = 50).

## What it does

`snowflake/migrations/V051__action_layer.sql` — the scoped action-layer slice:
creates `OW_ACTION_INTENTS` (idempotency) and `SP_ALERT_LIFECYCLE` (alert
ack/resolve as one transactional, set-based, idempotent proc). The app already
calls it **proc-first with a legacy fallback**, so behavior does not change
until this runs — and if you never run it, the app keeps using the v4.52 split
statements.

The remediation / verify-savings / action-queue procs from the first draft were
**deferred** after review found an owner-privileged SQL injection in the
unwired remediation proc (see docs/design/ACTION_LAYER_V051.md). They are a
separate, hardened round.

## Runtime-sensitive constructs to confirm on this run

This proc uses Snowflake Scripting features that only a live run fully proves —
the V047/V048 class of "looks right, verify on deploy":
- `SPLIT_TO_TABLE(:P_EVENT_IDS, ',')` bound inside `TABLE(...)`, values `TRIM`-ed.
- `SQLROWCOUNT` read immediately after each `UPDATE`.
- audit-INSERT-before-UPDATE inside one `BEGIN TRANSACTION` (statement-level
  snapshot consistency).

If any of these misbehaves, the guard/rollback surfaces a real error rather
than a silent wrong result.

## Run

## Verify

```sql
-- 1. Version: expect 51
SELECT MAX(VERSION) FROM DBA_MAINT_DB.OVERWATCH.SCHEMA_VERSION;

-- 2. Smoke the proc against a real open alert (or a throwaway id):
--    a bad/empty key is refused; a repeat is a no-op DUPLICATE.
CALL DBA_MAINT_DB.OVERWATCH.SP_ALERT_LIFECYCLE('', 'ACK', 'test', '', 'you', '');
--    -> BLOCKED: missing idempotency key
-- pick one OPEN event id and ack it (idempotency key any unique string):
CALL DBA_MAINT_DB.OVERWATCH.SP_ALERT_LIFECYCLE('<event_id>', 'ACK', 'smoke', '', 'you', 'smoke-1');
--    -> OK: 1 event(s) ACK   (exactly one ALERT_AUDIT row written)
CALL DBA_MAINT_DB.OVERWATCH.SP_ALERT_LIFECYCLE('<event_id>', 'ACK', 'smoke', '', 'you', 'smoke-1');
--    -> DUPLICATE: smoke-1    (no second audit row)
```

Then `snowflake/validate.sql` — top row reads `V001..V051 applied` — and in the
app, an alert ack/resolve now routes through the proc (the notify message no
longer mentions the split-statement path).

## Rollback

Idempotent and low-blast-radius: the proc is `CREATE OR REPLACE`, the table is
`CREATE IF NOT EXISTS`. To back out entirely, the V051 block in
`snowflake/teardown.sql` drops both. The app falls back to the legacy path the
moment the proc is gone.

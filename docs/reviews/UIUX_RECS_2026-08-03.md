Two parts. First, a review of the five design-wave commits (v4.123.0–v4.128.0)
that implemented the 2026-08-02 50-rec list. Second, **50 new code-verified
UI/UX recommendations** built on the post-wave state — user workflows,
interaction depth, and the follow-through the waves left open. Priority
P1 = do next round, P2 = queue, P3 = polish. Effort S/M/L.

freeze argument is correct. rec3 (`st.navigation`), rec6 (header breadcrumb),
rec8 (persist last section) were owner-skipped and are not re-proposed. All
earlier DECLINEs (no `st.tabs`, no dropdown nav, drawer stays, no palette

## A. Follow-through from the waves

**1. Re-establish wrap for segmented controls; retire the dead pill CSS (P1/S).**
`theme.py:157-168` still styles `div[role="radiogroup"][aria-label="Section"/
"Window"]` — the widget those selectors dressed is now the `hasattr` fallback
only, so the CSS (including the rec15 flex-wrap that kept every pill reachable
on narrow viewports) is dead on modern runtimes. `st.segmented_control` has no
wrap rule: Operations' 7 section pills and the 7-option Window control can
push options off-screen on a phone — the exact touch/keyboard trap rec15
fixed for radios. Add wrap CSS keyed to the segmented-control test-id and
move the radio selectors behind a "fallback only" comment.

**2. Finish the `empty_state` sweep (P1/M).**
The vocabulary shipped (`components.py:808`) but only two call sites adopted
it (`brief.py:220`, `alerts.py:886`); ~105 raw `st.info`/`st.success` sites
remain across pages (16 in operations.py alone). Until the sweep happens, the
"green = verified clean, never = nothing loaded" contract holds on two panels
and is aspirational everywhere else. Mechanical, parallelizable by page.

**3. Wire `counts=` where numbers are already in hand (P2/S).**
One pill is badged (Alerts → "Open events (N)", `alerts.py:705`). Zero-query
candidates: Admin → "Errors & telemetry" can badge the session error count
(session state, free); Control Room → "Incidents & triage" can ride the
health-strip values the shell already fetched. Skip any pill whose count
would cost a new query — the Alerts precedent is "already in hand only".

**4. Roll out `section_toc` to the other mega-sections (P1/S).**
Anchors + TOC exist on exactly one surface (Security → Access,
`security.py:73`). Alerts → History (six KPI/table blocks), Cost → Contract &
Forecast (seven panels), and Unit costs are the same shape and got nothing.
The component takes a list of tuples; each rollout is minutes.

**5. Roll out the `st.status` cold-paint wrapper (P2/S).**
Control Room (`control_room.py:358`) and Spend (`spend.py:98`) wrap their
first-paint read batches; Optimize's four subgroups and Alerts → History run
comparable multi-read cold paints bare. Same one-liner idiom.

**6. Roll out `clickable_bar_usd` beyond Overview (P2/S).**
One call site (`overview.py:581`). Spend → Attribution's user/database bars
and Optimize's `bar_usd` rankings are the same drill shape; the helper already
solved degrade + sticky-click, and Overview's caller shows the profile-gating
pattern. Each site is a few lines.

**7. Move the Views popover prefs read off the live tier (P2/S).**
`_views_popover` still runs the USER_PREFS read at `tier="live"` (30s TTL,
`main.py` ~196) — popover bodies execute on every rerun whether opened or
not, so every page pays this read twice a minute. Move to the `recent` tier
and bump a prefs domain salt on save (the write paths already exist), keeping
post-save freshness instant.

## B. Alert triage & incident workflow

**8. One-click ACK — risk-tier the confirm friction (P1/M).**
Acknowledging a single event requires typing `ACK` into a confirm field
(`alerts.py:594`) — the same ceremony as an emergency lever, applied to the
most frequent and fully reversible triage action. Make single-event ACK one
click (audit row and idempotency unchanged); keep typed confirms for RESOLVE
(it classifies rule precision), bulk, and anything destructive. Friction
should be proportional to risk, or operators stop acknowledging.

**9. Bulk-select on the events table itself (P1/M).**
The bulk flow re-lists open events as composed strings in a multiselect
(`alerts.py:617-635`) — the operator re-finds, in a dropdown, rows they were
just reading in the table. `st.dataframe(selection_mode="multi-row")` lets
them check rows in place; keep the multiselect as the degrade path and the
`BULK` typed confirm as-is.

**10. Rule track-record inside the drawer (P2/S).**
The ACK-vs-NOISE decision needs the rule's history, which lives on a
different section (Rules → `rule_precision(90)`). One line in the drawer —
"this rule: 62% actioned · 5 fires/30d · last close NOISE (2d ago)" — puts
the evidence where the decision happens; the frame is already cached when
Rules was visited, and it's one cheap aggregate when not.

**11. Per-event delivery state in the drawer (P2/M).**
The shell warns about undelivered criticals in aggregate and History has
delivery SLO panels, but the drawer can't answer "did THIS page reach
anyone?". Surface the event's own delivery record (delivered channel + time,
or "reached nobody") from the same bookkeeping the SLO panels read.

**12. Keep triage momentum after a lifecycle write (P2/S).**
After Execute, the rerun lands back on the now-closed event. Offer "Next open
event →" (or auto-advance the drawer selection to the next row) so working a
queue of ten doesn't require ten table re-selections.

**13. "Since your last visit" orientation line (P2/M).**
APP_USAGE records per-user page visits (V027). One line on Alerts/Control
Room — "14 new events since your last visit (Thu 14:02)" — reorients a
returning operator faster than re-scanning the feed for familiar rows.

**14. A guarded snooze for noisy rules (P2/M).**
The fatigue panel diagnoses noise (`alerts.py:860-869`) but the only remedy
is hand-editing ALERT_CONFIG in Snowsight. A "suppress until <date>" write
next to the fatigue verdict — SQL preview + `confirm_gate`, audited, visible
on the Rules table as a SNOOZED badge — closes the loop on the panel that
surfaces the problem. Needs a column/flag in ALERT_CONFIG (owner migration).

## C. Drill paths & cross-page flow

**15. A one-hop "back" after cross-page jumps (P1/M).**
Investigate →, Generate fix →, score-driver Investigate, and the clickable
bar all navigate away with filters applied; returning means rebuilding where
you were by hand. Record the origin (page/section/filters — the exact payload
Views already serializes) when `request_navigation` fires, and render
"← Back to Alerts · Open events" in `page_header` for one hop. Depth-one
only; no history stack.

**16. Warehouse names drill everywhere (P2/M).**
WAREHOUSE_NAME appears in ~10 read-only tables (attribution, movers, idle
advisor, concurrency peaks) with no path to Operations → Warehouses scoped to
that warehouse. `selectable_nav_table` exists precisely for this; wire the
cost-side warehouse tables to it with the executive profile-gating from the
rec40 pattern.

**17. User names drill to their queries (P3/M).**
`with_user_names` decorates tables with display names, but a user row is a
dead end; the DB jump (`main.py` r6-bug9) proves the pattern for carrying
scope. Row-click → Operations → Queries with `user_contains` set.

**18. "Copy link to this view" (P1/S).**
`?page=` and `?section=` are in the URL but filters are not, so a pasted link
drops company/window/database scope. Add a "Copy link" affordance in Views &
display that emits the full URL with a serialized filter payload (the saved-
view JSON, urlencoded) and teach `_apply_default_landing`'s deep-link branch
to hydrate it. Sharing a scoped screen is the collaboration primitive the
app is missing.

**19. Unify the query-drill idiom (P2/M).**
Ops → Queries drills through a separate selectbox/paste-an-ID flow while
newer surfaces use row-selection (alerts drawer, triage queue). Converge on
selected-row → detail card below the table, keep paste-an-ID as the fallback
for IDs from outside the visible window.

## D. Time & scope controls

**20. Custom date range (P2/M).**
Windows are presets only (7…365). Investigations are calendar-shaped ("the
June 12 incident", "since the release"). Add "Custom…" to the window control
revealing a from/to pair, mapped through the same clamps (`bounded_days`,
90d live cap) with the same over-cap disclosure. Release compare and Day
replay already prove the need with their own local date pickers.

**21. Badge page-local time controls (P2/S).**
Release compare (`operations.py`) and Day replay (`control_room.py`) use
local date inputs that silently ignore the global Window; a viewer reading
"last 30d" in the filter strip above a 7-day compare has no cue. A small
"local window" chip on those panels (one `chip()` call) prevents the misread.

**22. Demote the Environment picker (P2/S).**
Its own help text admits it "narrows the Database picker only"
(`main.py:573-578`) yet it sits as a peer of Company/Window, reading like a
scope every query honors. Fold it into the Database control (an optgroup-like
prefix or a small selector inside that column) so the toolbar's four slots
are all real scopes.

**23. Per-chip clear on the header scope chips (P3/M).**
The header chips (`_scope_chip_html`) are display-only; correcting one filter
means finding its control or nuking everything with Reset. Making each chip
clearable (small ✕ buttons rendered beside the chips) turns them from
decoration into scope controls.

**24. Disclose partial-day windows on tables (P3/S).**
The spend chart dims today as provisional; tables in the same windows include
today's partial day with no cue. Extend the rec31 size caption with
"includes today (partial)" when the window's end is today — one condition in
`_render_table`, honesty parity with the chart.

**25. Show the active-filter count on the collapsed strip (P3/S).**
The filter strip glows when scope is non-default, but *which* and *how many*
filters are live requires opening "More filters". Append the count to the
kicker — "Triage filters · 2 active" — so a hidden `user_contains` can't
silently shape every number on the page.

## E. Reading the numbers

**26. Humanize durations at the display layer (P1/S).**
Ops tables print raw `QUEUED_SEC`/`ELAPSED` numbers ("5,400" seconds) and
minutes with one decimal; scanning is arithmetic. Add a duration formatter to
the `_auto_formats` convention (`_SEC`/`_MS` suffixes → "1h 30m" / "850ms"),
display-only, CSV keeps raw values — same contract as header prettifying.

**27. Relative time beside triage timestamps (P1/S).**
RAISED_AT/LAST_SEEN render as absolute account time; the operator's first
question is "how stale?". Append a display-only "· 3h ago" (computed at
render, account-time based) to the timestamp column in the alerts feed,
incidents, and triage queue tables.

**28. Dollars-primary, credits-secondary on every headline cost KPI (P2/S).**
The sidebar strip now shows "$X MTD · N cr" (rec13); Overview/Brief cards
show one unit or the other. Adopt the dual format on the MTD and window-spend
cards (dollars big, credits in the meta line) — reconciling against Snowsight
credit numbers is a daily task and currently needs mental math.

**29. "vs prior window" deltas on the Control Room pulse (P2/M).**
Pulse KPIs show absolute counts and a fail% (`control_room.py` Pulse
section); nothing says whether 42k queries is normal. The hourly facts hold
the history — add "vs same span last week" deltas using the existing
`kpi_row` delta slot, same basis note as the spend pace.

**30. Declare the sort in the size caption (P1/S).**
`severity_sort` documents alert ordering, but cost tables' order is whatever
the SQL emitted, undeclared. Extend the rec31 caption to "142 rows · by $
desc · last 30d" (callers pass a `sort_label`); a reader should never have to
infer whether a list is ranked or arbitrary.

**31. Unit suffixes in prettified headers (P3/S).**
`_prettify_header` title-cases but leaves bare unit tokens: "Elapsed S",
"Spill Remote GB", "Queued Sec". Map the known unit suffixes to parenthesized
display units — "Elapsed (s)", "Remote spill (GB)" — in the same keep-list
pass (`components.py:851-861`).

## F. Tables & charts, round 2

**32. Quick-filter box on large tables (P2/M).**
Tables >100 rows (grants, heaviest queries, chargeback detail) offer only
scroll; the global contains-filters re-run queries and change scope. An
opt-in text input above the table filtering the already-fetched frame
(case-insensitive contains across string columns) is instant, display-only,
and leaves the CSV complete.

**33. Opt-in totals row on cost tables (P2/M).**
Attribution and chargeback tables don't show their own sums, so "does this
reconcile with the KPI above?" needs the CSV and a spreadsheet. An opt-in
bold totals row (styled_table `totals=` param, computed on the numeric
columns) answers additivity questions in place — the app's own honesty rules
lean on additivity (V048).

**34. Curated default columns for the widest tables (P3/M).**
Several detail tables carry 12+ columns and force horizontal scroll for the
common read. Keep a per-table display allowlist (full frame still exported)
so the on-screen view is the reading view; the pinned-first-column work
already acknowledges the scroll problem.

**35. Change-event annotations on the spend trend (P2/M).**
`daily_metric_line` already supports a `rule_date`; the change registry and
incident starts are queryable. An opt-in overlay of change markers on
`spend_trend` ("what happened that day") turns the most-viewed chart into the
correlation surface operators currently reconstruct by tab-switching.

**36. Interval-brush zoom on long-window charts (P3/M).**
At 180/365d, inspecting one week means changing the global window and losing
context. An x-axis `selection_interval` bound to the scale (display-only
zoom, double-click to reset) on `spend_trend` and the monthly boss chart
keeps the investigation local.

**37. Unified hover on layered charts (P3/S).**
`spend_trend`'s bars and 7-day-average line answer to separate hovers with
tiny bar targets. A shared vertical hover rule emitting one tooltip (day,
spend, avg — the `tip` list already carries all three) makes the flagship
chart readable by sweep instead of hunt.

**38. One takeaway voice (P3/S).**
Three phrasings coexist: `_share_note`'s "Top: X $Y (Z% of $T)."
(`charts.py:92-102`), spend_trend's hand-built pace sentence, and Overview's
"Top driver: **X** — …" (`overview.py:567-569`). Pick one voice and number
style and route all three through the helper so conclusions read like one
author wrote them.

**39. "Now" marker on the event timeline (P3/S).**
`event_timeline` spans days of dots; recency requires reading axis labels. A
subtle now-rule at the right edge plus a faint last-24h band makes "old vs
fresh" pre-attentive on the correlation strip.

## G. Write actions & feedback, round 2

**40. In-flight state on execute buttons (P1/M).**
Between click and result, execute buttons stay enabled and the UI says
nothing; a nervous double-click sends twice (idempotency keys absorb it
server-side, but the UX is a shrug). Set a session busy-flag around
`execute_action`: button disabled + "Executing…" label during the round
trip, cleared on the rerun that carries `notify()`.

**41. Post-write receipt with an evidence link (P2/S).**
`notify()` toasts the outcome; trust closes when the operator can see the
audit row. Append "view audit →" to success notifications for lifecycle/
remediation writes, deep-linking to the audit surface (Admin → Errors &
telemetry or the relevant history panel) via `request_navigation`.

**42. Reopen for mis-resolved events (P2/M).**
RESOLVE is one-way in the UI — a mis-click removes an event from the queue
with no recovery except SQL. A guarded REOPEN on recently-resolved events in
History (typed confirm, audited, resets the dedupe key) needs a small
`SP_ALERT_LIFECYCLE` extension — owner migration — but the dead-end is a real
operator trap today.

**43. Modal parity for the remaining destructive singles (P2/S).**
`st.dialog` shipped for the account-level emergency lever only
(`operations.py:1000`). Kill-query (`operations.py:1048`) and incident
close/declare (`control_room.py:401,421`) still confirm inline beneath
ambient page content. Same hasattr-gated modal, same inline fallback.

**44. Impact preview parity for table-touching writes (P2/M).**
Warehouse suspend/resize confirms render `blast_radius` (who you'd
interrupt); the storage-waste retention change (`optimize.py:754`) executes
against a table with no equivalent "who reads this" preview. Surface the
candidate's last-read / last-DML evidence (already computed by the waste
scanner) directly above that confirm gate.

**45. Progress for multi-read builds (P3/S).**
`st.progress` exists only on the Admin canary loop. The auditor zip pack
(Security) and the reconciliation builds iterate multiple reads with no
feedback; reuse the canary's progress idiom (n-of-m with `progress.empty()`
on completion).

**46. Success = toast, error = persistent — one notify policy (P3/S).**
`notify()` always does both toast and inline. On flows that immediately
rerun, the inline success flashes and vanishes (noise); on failures the
inline message is the record and must stay. Codify: success → toast only
(plus the receipt link from item 41), failure → toast + persistent inline.
One change in `components.py:1088-1094`, app-wide consistency.

## H. Shell, onboarding & accessibility

**47. Setup-progress checklist on Admin (P1/M).**
Fresh installs discover missing pieces panel-by-panel through per-panel
hints. One "Setup" panel with green/pending rows — migrations at floor
(SCHEMA_VERSION), marts loading (SOURCE_FRESHNESS_STATE), delivery routes
(ALERT_ROUTES), budget/contract configured (SETTINGS) — all queryable today,
turning twenty scattered `needs_setup` hints into one linear onboarding
surface with links to each fix.

**48. Health-strip lines as entry points (P2/S).**
Only the criticals line is a button; "Stalest telemetry: X 9h" and the MTD
line are inert text. Deep-link the stale line to Control Room → Freshness &
replay (now addressable via `cr_section`, a wave 2 win) and MTD to Cost &
Contract — the always-visible rail should be the fastest way into the app,
not a readout.

**49. A "what's new" surface (P3/S).**
Five design waves shipped in one day; operators discover new affordances
(count badges, jump-to sections, one-click windows) only by accident.
Render the newest CHANGELOG section in a collapsed expander (Admin, or the
Views & display popover) — the file ships with the app; zero new content to
maintain.

**50. Perceivability pass on the new interactive chrome (P2/M).**
Three gaps: `icon()` SVGs carry no `aria-hidden`/`role`, so screen readers
meet anonymous vector soup on every header; clickable surfaces are invisible
as such — `clickable_bar_usd` and `selectable_nav_table` give no cue that
rows/bars respond to clicks (Overview writes its own caption; make a standard
`hint=` on both helpers); and the focus-visible treatment that existed for
the retired pill radios should be verified on `st.segmented_control` before
the fallback path atrophies. One sweep, all three.

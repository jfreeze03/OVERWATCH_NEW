# UI/UX recommendations — v4.129–v4.148 review + 50 items — 2026-08-12 (main @ 4d9c757, v4.148.0)

Two parts. First, a review of the twenty releases since the 2026-08-03 list
(readability waves, cost evidence, task-graph workbench, operating workbench,
Decision Studio, investigation routing, security posture, correctness fixes).
Second, **50 new code-verified UI/UX recommendations** for the post-workbench
state. Priority P1 = do next round, P2 = queue, P3 = polish. Effort S/M/L.

**Honored decisions:** Security stays a read-only posture surface (v4.146
owner correction — nothing here proposes a policy/review write surface); no
new warehouses (v4.144.3 CI guard); `st.form` stays declined for
live-SQL-preview flows; heuristics stay labeled (v4.145); rec3/6/8 from
2026-08-02 stay skipped. Migration-needing items are flagged for the owner's
next V0XX.

## Part 1 — Review of v4.129 → v4.148

**Verdict: the app crossed from "monitor" to "operating console" in nine
days, and the seams show in predictable places.** What shipped well: the
readability waves landed cleanly (humanized durations with the large-frame
unit fix, Age columns that preserve row-selection mapping, declared sorts,
Σ totals); the new contract primitives are genuinely good design —
`decision_rows` forces every decision surface to state what its Impact $ and
Confidence *mean* (`components.py:1511-1534`), `filter_contract_text` makes
scope explicit per section, `evidence_gate`/`read_model_caption` make read
costs legible, and `navigation_context` (`state.py:146-149`) correctly
separates drill identity from global filters. The v4.135 a11y pass fixed the
segmented-control wrap regression flagged on 08-03, and the clickable global
pulse consolidated three shell readouts into one routed surface. Two owner
corrections in the window (Security trimmed back; `WH_OVERWATCH_APP`
reverted + CI guard) are respected throughout this list.

**Where the seams are (verified, feeds Part 2):**
- **Consistency debt on the new surfaces:** workbench writes (save/create
  work item, SLO create, experiment save) use bare primary buttons while
  incident close/declare use typed `confirm_gate` — no articulated policy;
  `st.subheader` and markdown mini-headers crept back in
  (`control_room.py:746`, workbench/day-replay); Operations has **zero**
  `empty_state` calls; `sizing.py` tokens are imported by only 3 of 10 page
  files; Cost Truth KPIs render credits with no dollars.
- **Routing half-adopted:** the triage queue computes and then **drops**
  EVENT_ID/RULE_ID on navigation (`control_room.py:656-663`), task-failure
  rows land on Operations with no section or task context, and there are two
  different `investigation_target` functions with opposite payload semantics
  (`logic/workbench.py:358-375` context vs `logic/navigate.py:103-124`
  filters).
- **Aug-03 carry-forwards confirmed unshipped:** one-click ACK, feed-table
  bulk selection, per-event delivery state, auto-advance, snooze, copy-link,
  back-breadcrumb, what's-new, setup checklist, notify policy, in-flight
  execute state, and the Views-popover prefs read still on the live tier
  (`main.py:201`).

## Part 2 — 50 recommendations

**Do-first shortlist (P1):** 1, 4, 8, 14, 20, 23, 27, 29, 42, 44.

## A. Carry-forwards that still bite (verified unshipped)

**1. One-click ACK (P1/M).**
Still typed: acknowledging one event requires typing `ACK`
(`alerts.py:608-610`) — emergency-lever ceremony on the most frequent,
fully reversible triage action. One click for single ACK (audit + idempotency
unchanged); typed stays for RESOLVE (classifies precision), bulk, and
destructive levers. This is now also the model for item 14's policy.

**2. Bulk-select on the feed table (P2/M).**
Bulk still re-lists events in a multiselect of composed strings
(`alerts.py:628-659`). `selection_mode="multi-row"` on the feed the operator
already reads, multiselect as degrade path, `BULK` confirm unchanged.

**3. Copy-link-to-view (P2/S).**
`?page=`/`?section=` exist; filters still aren't shareable. A "Copy link"
in Views & display emitting the full URL (the saved-view JSON payload,
urlencoded) plus deep-link hydration makes any scoped screen pasteable —
the collaboration primitive the app still lacks.

**4. One-hop "back" after cross-page jumps (P1/M).**
Investigation routing multiplied cross-page jumps (Investigate →, Entity
360, triage rows, pulse targets) and there is still no return path.
`request_navigation` already has everything needed to record the origin
(page/section/filters/context); render "← Back to Control Room · Incidents &
triage" in `page_header` for one hop, no history stack.

**5. `empty_state` sweep, round 3 — with a drift test (P2/M).**
Adoption spread to security_center/spend/optimize but Operations still has
zero calls and Overview mixes raw `st.info`/`st.success`. The two prior
sweeps prove intent doesn't stick without teeth: add a source-grep test
(the house shape-test idiom) that pins per-file raw-empty-state counts and
ratchets them down, like the ACCOUNT_USAGE literal budgets.

**6. Height tokens, same treatment (P2/S).**
`sizing.py` is imported by Overview/Brief/Admin only; Ops/Security/Cost and
the new workbench surfaces hardcode 140–680 (DAG 680/620, Products 390,
Portfolio 370, Action Center 340). Migrate and add the consumer-drift test —
`test_palette_drift.py` is the template.

**7. Views-popover prefs read off the live tier (P3/S).**
Still `tier="live"` (`main.py:201`) — every page pays a 30s-TTL USER_PREFS
read per rerun for a popover that's rarely open. `recent` tier + a prefs
domain-salt bump on save.

## B. Control Room information architecture

**8. Promote Decision Studio to a top-level page (P1/M).**
Control Room now carries 7 sections; Decision Studio nests 6 more inside it,
and Entity 360 nests 2 — three navigation levels before content, and the
morning-triage surface shares a roof with a planning studio that has a
different cadence (daily triage vs weekly planning). Move Decision Studio to
its own page under Analyze (`NAV_GROUPS` has room; `PAGES_BY_PROFILE` gates
it), leaving Control Room as the triage console: Action Center · Pulse ·
Incidents · Timeline · Freshness. Deep links keep working via
`PAGE_SECTION_LABELS`.

**9. Split "Timeline & movers" (P2/S).**
Correlation timeline, lock-wait spikes, and top-10 spend movers are three
unrelated reads stacked in one section (`control_room.py:691-779`). Movers
are a cost concern — move them to Pulse's bottom or Cost; lock spikes join
the timeline as a lane rather than a separate table (the replay chart
already does lanes).

**10. Exception-first ordering in "Incidents & triage" (P2/S).**
The section stacks incident KPIs, proposals expander, then the triage queue.
Lead with the `exception_summary` (the idiom Pulse and Action Center
already use), then the queue, then proposals — the operator's first question
is "what needs me", not "what's proposed".

**11. Count badges on Control Room pills (P2/S).**
Action Center's open count and Incidents' open count are computed by their
sections' own summaries; the health strip the shell already fetched carries
open criticals. Badge the pills the way Alerts → "Open events (N)" already
does — zero-extra-query counts only, per the established precedent.

**12. Entity 360 entity pickers (P2/M).**
The Entity tab asks for a typed key (`workbench.py:411-433`); "Query
fingerprint" expects a hash nobody memorizes. Populate a per-type selectbox
from the entity catalog / portfolio frame (both already queryable), keeping
the free-text input as the escape hatch. First-run with no context should
offer the catalog, not a blank.

**13. Heading-system parity on the new surfaces (P3/S).**
`st.subheader("Lock-wait spikes…")` (`control_room.py:746`) and the
markdown mini-headers through workbench/day-replay bypass `section_header`
(stripe + icon + severity). Same one-pass migration as the v4.125 sweep,
plus the grep test to keep it done.

## C. Write-action policy on the workbench surfaces

**14. One articulated write-friction policy (P1/M).**
Today: incident close/declare = typed `confirm_gate`; action save/create,
SLO create, experiment result save, ownership edit = bare primary button
with SQL preview (`workbench.py:171-236, 341-366`; `decision_studio.py`
SLO/experiment paths). Neither extreme is wrong — the *inconsistency* is.
Codify: app-table upserts (OVERWATCH's own queue/records) = one-click +
receipt; anything touching account objects or classifying evidence = typed
gate. Write it into CLAUDE.md's laws and align the ~8 sites — this also
resolves item 1 by policy rather than exception.

**15. In-flight execute state (P2/M).**
Carried from 08-03 and now more visible: workbench saves, experiment
updates, and lifecycle calls all leave the button clickable during the
round trip. One session busy-flag wrapper around `execute_action`/
`execute_statement` call sites (disable + "Executing…"), cleared on the
rerun that carries `notify()`.

**16. Post-write receipt on action transitions (P2/S).**
`action_transition_sql` writes an activity row the detail pane renders —
but after Save the user must find it themselves. Toast "Saved — logged to
activity" and scroll-anchor/highlight the new activity row (it's the
freshest row in a table already on screen).

**17. No silent row-0 in Experiments (P3/S).**
The experiments detail renders index 0 when nothing is selected
(`decision_studio.py:393-394`) — an unselected page appears to be *about*
the first experiment. Either require selection (empty detail + "select an
experiment") or label the default explicitly ("Showing newest experiment").

**18. Scenario tab needs its empty states (P3/S).**
Post-V074 with an empty action queue, the three sliders render over nothing
and project $0 silently. `empty_state("no_data_yet", …)` + disabled sliders
until estimates exist — the sliders imply there's something to model.

**19. Duplicate-work-item guard (P2/M).**
Work items can now be created from Action Center and Security
(`security_center.py:185-206`) against the same entity. Before create,
show open items for that entity ("2 open items for WH_X — open instead?") —
the dedupe-key discipline alerts already enforce, applied to the manual
path.

## D. Identity routing, finished

**20. Triage rows carry their identity (P1/S).**
The triage queue computes EVENT_ID/RULE_ID and then navigates with
page/section only (`control_room.py:656-663`) — while the Alerts drawer
already consumes an `event_id` context and self-selects
(`alerts.py:333-376`). Pass `context={"event_id": …}` and the morning
queue's biggest dead-end disappears. Small, high-value, all plumbing
present.

**21. Task-failure triage lands somewhere (P1/S).**
Task rows route to `("Operations", "")` — no section, no task. Route to
Operations → Tasks (Health) with the task name in context; the workbench
already seeds from `navigation_context`.

**22. Spend-anomaly triage carries the warehouse (P2/S).**
Anomaly rows land on Cost's top with no scope. Carry the warehouse via
context (or `warehouse_contains` where the target panel is filter-driven) so
"investigate this spike" doesn't restart at account-wide.

**23. One router, one semantics doc (P1/M).**
Two `investigation_target` functions coexist: `logic/workbench.py:358-375`
(returns context — identity) and `logic/navigate.py:103-124` (returns
filters — scope reshape). They serve different intents but share a name and
live in different modules; the next contributor will pick the wrong one.
Merge into one module with two explicitly-named entry points
(`identity_target` / `scoped_target`), and document the filters-vs-context
law in CLAUDE.md — AGENTS.md already warns about the filter-leak trap.

**24. Announce filter-applying jumps on arrival (P2/S).**
Alert "Investigate →" deliberately reshapes global filters
(`alerts.py:581-584`); after landing, nothing says so except the filter
strip's count. A one-line arrival note — "Filters applied from alert
[COST_WH_SPIKE] — Reset" — prevents the next page view from being silently
scoped (pairs with item 4's origin plumbing).

**25. DAG nodes click through to Entity 360 (P2/M).**
The SVG renderer has find/zoom/fullscreen but a node click does nothing;
task drill lives only in the Run analyzer's table. A node click (or a
"selected node" panel with an Open Entity 360 button) closes the loop the
renderer already visually invites.

**26. Entity 360 says which types have no metrics (P3/S).**
`ENTITY_METRIC_TYPES` excludes ALERT/INCIDENT/ACTION/DATA_PRODUCT — those
profiles render ownership with silently absent metrics. One caption ("No
metric snapshot for this entity type — evidence and actions below") keeps
the blank from reading as broken.

## E. Decision-surface readability

**27. One priority language (P1/M).**
Three ranking vocabularies coexist: `rank_actions` (severity → overdue →
$ → age), the triage queue's severity/$ sort, and the portfolio's
PRIORITY_SCORE. Each is defensible; together they mean "priority" never
means the same thing twice. Publish the three rules in the Legend popover,
name the columns distinctly (Queue rank / Portfolio score), and state each
surface's rule in its `sort_label` — the reader should never transfer a
ranking intuition between surfaces wrongly.

**28. Make the two Confidences visually distinct (P2/S).**
Portfolio Confidence is an evidence heuristic; Action Center Confidence is
an authored belief — same ProgressColumn, different epistemics, currently
distinguished only by column help (v4.145). Add a visible tag in the column
label ("Confidence (evidence)" vs "Confidence (authored)") so the
distinction survives skimming, not just hovering.

**29. Cost Truth in dollars too (P1/S).**
The four basis KPIs render credits only (`decision_studio.py:281-312`)
while the whole app leads with dollars and the sidebar pulse shows both.
Dual-format each lens (dollars primary at its correct rate, credits
secondary) — the AI/OTHER split rule applies (blended for BILLED; the
metric registry knows each basis).

**30. Scenarios drill to the action (P3/S).**
The scenario estimate table has no row action; clicking an estimate should
open its work item in Action Center (context plumbing from item 20's
pattern). Planning without a path to the plan's objects stays theoretical.

**31. Lane chips on the portfolio (P2/S).**
ACT NOW / PLAN / VALIDATE counts live in the exception strip and the rule in
a caption. Add lane filter chips above `decision_rows` (client-side frame
filter) so "show me just ACT NOW" is one click — the table is 370px of
mixed lanes today.

**32. Products table: declare non-additivity where the eye sums (P3/S).**
Object-attributed $ and warehouse-metered $ are correctly separate,
non-additive columns — stated in a caption. Suppress totals (`totals=`
deliberately absent — keep it that way) and put the non-additive note in
the column help of both columns, where the summing impulse happens.

**34. Root picker sorts by trouble (P2/S).**

**35. Tokenize the renderer heights + verify fullscreen on SiS (P3/S).**

pages, and the renderer is an iframe embed — `charts.py:291+`).

**36. DAG search with match count and stepping (P2/M).**
Find is substring-highlight only; on a 300-node graph "found where?" needs
"3 of 7 · next/prev" stepping that pans to each match — the toolbar and
keyboard plumbing already exist (`charts.py:370-377, 493-538`).

**37. Version-compare empty state teaches (P3/S).**
With <2 recorded versions it has nothing to say; say what creates versions
and link the Runs view ("versions appear as the graph changes — 1 recorded
so far") instead of a bare empty.

## H. Shell & onboarding

The projector/print HTML + slides + CSV trio (v4.134) is the most
exec-facing feature in the app and lives at the bottom of a 900-line
Overview scroll and inside a collapsed Brief expander. Render it via
`export_button` in a consistent header-right position on both pages — the
audience least willing to hunt is the one it serves.

**43. What's-new surface (P2/S).**
Carried, and the argument strengthened: twenty releases shipped in nine
days, including whole new surfaces. Render the newest CHANGELOG section in
a collapsed expander in Views & display; zero content maintenance.

**44. Setup checklist, now with V074/V075 (P1/M).**
Carried, and the pending-migration walls multiplied: Action Center, Entity
360, SLOs, experiments, and the Security decision queue all `needs_setup`
individually. One Admin "Setup progress" panel — migrations at floor, marts
loading, routes configured, budget/contract set, V074 workbench live, V075

**45. Merge Jump-to and Investigate into one palette (P2/M).**
The sidebar now stacks a Jump-to selectbox and an Investigate expander
(type + ID + button, `main.py:404-435`). One input that pattern-detects
(UUID → query, `evt_`/numeric → alert/action, name → entity/page/section
candidates) with a kind picker only on ambiguity — command palettes
shouldn't ask the user to classify first.

**46. Timezone visibility on timestamps (P3/S).**
Tables render account time with no unit until a display timezone is chosen
(and the note shows once per page). Add the zone abbreviation to the first
timestamp column's display label ("Raised At (CT)") via the prettifier —
the single most common misread of raw timestamps costs nothing to prevent.

## I. Consistency & trust polish

**47. Compact filter contracts after first exposure (P3/M).**
`section_filter_contract` lines are load-bearing but verbose ("Applies … |
Panel-dependent … | Active but ignored …") and now render on every major
section. Keep the full sentence in a hover/help; render the compact form
(`Scope: company · window · +2 ignored`) inline — same truth, less chrome
per screen.

**48. One notify policy (P3/S).**
Carried: `notify()` still always toasts *and* prints inline
(`components.py:1604-1610`). Success → toast (+ receipt link, item 16);
failure → toast + persistent inline. One change, app-wide calm.

**49. Scope the Security read-only claim precisely (P2/S).**
The page caption says it "does not grant or revoke anything"
(`security.py:790-792`) while "Track as work item" writes to OVERWATCH's
own queue (`security_center.py:185-206`). Both are right; the caption
should say so: "reads account state; writes only to OVERWATCH's own work
queue." Post-v4.146, this page's posture claims deserve exactness.

**50. Badge the remaining pills where counts are in hand (P3/S).**
Alerts' pill badge shipped; Security's posture exceptions and Cost's
unmapped-entities count render above their pills and could badge them
(zero-query rule as always). Counts on pills are the cheapest triage
signal the app has — finish the rollout.

# UI review — color scheme + section display (2026-08-14)

Owner ask: "I do not like the color scheme and some of the sections need to be
displayed better." This is the review-and-recommend round; nothing here is
implemented yet. Every claim cites the line it was verified against
(v4.154.0, `a144f3a`). Recommendations are split into an owner-pick
(the palette direction) and a ship-list Joe can approve item by item.

---

## Part 1 — Color scheme

### Diagnosis: why it reads generic

1. **Everything that isn't a severity is the same blue.** Background
   `#0a0f1c`, surface `#0f1729`, raised `#131d33` are all blue-tinted slate;
   the accent is sky `#38bdf8`; INFO severity is the same sky; the brand dot,
   wordmark gradient, focus rings, links (`config.toml` primaryColor), the
   "live" source badge, and the scope glow are all that one hue. The page is
   a monochrome blue wash with red/amber/green severity pops.
2. **ACCENT == INFO is a semantic collision.** `app/ui/palette.py:24-27`
   says it outright ("INFO doubles as the sky accent"). "This is clickable /
   selected" and "this is informational" are indistinguishable — an
   info-striped card looks selected, a primary button looks like an info chip.
3. **It is the stock Tailwind-400 dark-dashboard palette.** sky-400,
   cyan-400, emerald-400, amber-400, rose-400, orange-400 on slate-900
   surfaces, with an Inter font stack (`app/theme.py:37`). This is the
   default look of a thousand AI-generated dashboards — a likely root of the
   "I don't like it" reaction even before the semantics.
4. **Gradient/glow overuse compounds the wash.** Metric-card background
   gradients (`app/theme.py:60`), stripe gradients (`63-64`), sky→cyan
   gradient bars in four chart builders (`app/ui/charts.py:573-575, 627-629,
   656-658, 708-710`), gradient wordmark text + pulsing brand dot
   (`app/theme.py:174-181`), button hover glow (`204`), selected-pill
   gradient (`199-200`), sidebar gradient (`232`), scope-glow border
   (`170-172`).
5. **Two unrelated categorical palettes coexist.** The Altair theme's
   category range is house hues + two chart-only extras
   (`app/ui/charts.py:60-61`), but every *stacked* chart colors by the
   crc32-stable `_STABLE_PALETTE` — which is tableau10 (`729-730`), a palette
   that shares no hue with the theme. Overview shows both on one screen
   (monthly stacked vs. driver bars).

### What makes a recolor cheap here (and what doesn't)

The token layer is genuinely good: `--ow-*` custom properties
(`app/theme.py:21-39`), one palette module (`app/ui/palette.py`), and
`tests/test_palette_drift.py` enforcing three-file lockstep
(theme.py + palette.py + `.streamlit/config.toml`). Severity hues can stay
under any option below, which keeps `status_colors.py`'s table tints and the
drift test's `_SEVERITY_HUES` pin untouched.

Residual literals a recolor must chase (step 0 is tokenizing these so palette
candidates can be tried as a 3-file edit):

- `app/theme.py`: 13 sky literals/rgba (`rgba(56,189,248,…)` hovers, glows,
  multiselect chips, focus rings), primary-button ink `#06121f`,
  multiselect text `#dbeafe`.
- `app/ui/charts.py`: `_GRID` slate rgba (24), `_TITLE #c3cddb` (26) + the
  spend-trend average line (587), paired-bars dim side `#64748b` (1173),
  dark point strokes `#0a0f1c` ×3 (956, 985, 1029), and the task-DAG HTML
  template's ~12 chrome hexes (323-384) — make the template consume palette
  via the existing `.replace()` mechanism.
- `app/assets/favicon.png` — the sky radar mark; regenerate or accept the
  mismatch.

### Owner pick — three directions (A recommended)

**Option A — "Graphite & violet" (recommended).** Neutralize the chrome so
data colors carry all the meaning; give interaction its own hue distinct
from INFO.

```
--ow-bg:#101114  --ow-surface:#17181c  --ow-raised:#1e2127
--ow-hairline:rgba(164,170,182,0.16)   --ow-hairline2:rgba(164,170,182,0.28)
--ow-ink:#edeff4 --ow-ink-soft:#b5bbc6 --ow-ink-mute:#8e95a2
--ow-accent:#a78bfa   (violet — interaction/selection/brand only)
--ow-accent2:= accent (retire the cyan gradient partner)
OK/WARN/BAD/HIGH unchanged; INFO stays #38bdf8 and is now distinct from accent.
primary-button ink: #140f26
```

Rationale: warm accents (amber/orange) collide with WARN/HIGH, greens with
OK, pinks with BAD — violet is the one distinctive hue family with no
severity collision. Neutral (non-blue) surfaces stop the wash and make the
severity colors visibly *the* color on the page. The rec15 a11y contract
(muted labels ≥ 4.5:1 on every surface, `app/theme.py:24-26`) must be
re-verified at implementation; the proposed ink-mute is at the same
lightness as the current token.

**Option B — "Keep sky, lose the wash" (smallest diff).** Keep every hue;
change only bg/surface/raised to the Option-A graphite values and apply the
de-slop list below. Accepts the ACCENT==INFO collision as a known trade.

**Option C — light theme.** Honest scoping: `status_colors.py` already
carries light pairs (25-32), but theme.py, the Altair theme, and the DAG
template are dark-tuned end to end. This is a second theme, not a token
swap — only worth it if a light app is actually the preference.

### De-slop list (applies under any option; each is a one-line or CSS-only edit)

1. Flatten metric-card / stat-card / ow-card backgrounds to solid
   `var(--ow-surface)`; keep the 3px severity stripe (it carries meaning)
   and the hairline border; drop the gradient + hover glow-shadow.
2. Solid accent bars in the four gradient chart sites.
3. Solid selected pill / nav highlight (no gradient).
4. Static brand: solid-ink wordmark, non-animated accent dot (kill the
   gradient text + pulse, `app/theme.py:174-181`).
5. Drop the button hover glow (`204`); hairline color change is enough.
6. Replace `_STABLE_PALETTE` (tableau10) with a 10-hue set derived from the
   house palette so stacked charts and the rest of the app share one family.
   Keep the crc32 name→color stability contract; update its test to the new
   range (strengthen, never delete — AGENTS.md shape-test rule).

## Part 2 — Section display

Ranked ship-list. S1-S4 are the visible wins; S5-S7 are polish.

**S1. Show the filter-contract band only when it prevents a misread.**
Today every section opens with three chrome elements before any number:
`section_header` + `section_filter_contract` (a full-width tinted band of
scope metadata) + the `panel_help` popover — e.g. Overview "Company
economics" (`app/ui/pages/overview.py:548-559`) and Cost, which prints a
contract band under the pills for *every* section (`app/ui/pages/cost.py:97`).
The band's honest job (rec11) is the "Active but ignored: …" case; the
default "Applies: Company · Window" case is noise on the common no-filter
path. Change `section_filter_contract` (components.py:386-400) to render the
band only when `partial`/`ignored` content exists, and fold the "Applies"
sentence into the section header's existing badge slot or the ⓘ popover.
One components.py change lifts every page; it is the same philosophy
`section_scope_note` already implements (components.py:403-423 returns ''
when nothing active is ignored).

**S2. Status bar: one affordance, and a label bug.** The four pulse cards
render a second row of tertiary buttons whose labels compose as
`f"Open {label.lower()}"` → **"Open open criticals"**, "Open mtd spend"
(`app/ui/components.py:536-537`), pinned under the cards with a −14px margin
hack (`app/theme.py:152-153`). Make the card itself the click target (or a
single compact "→" affordance per card) and delete the button row.

**S3. Give nested pill rows a visual hierarchy.** Operations stacks three
*identical-looking* segmented rows: page sections
(`app/ui/pages/operations.py:1453`) → Tasks Health/Graph/Runs (`929`) →
Graph Topology/Analyzer/Compare (`871`). A reader cannot tell which row owns
which. Wrap `nested_sections` in a keyed container (the `st-key-*` CSS
pattern already used for `ow_status_actions`) and style inner rows smaller /
borderless with an underline-style selected state instead of the filled pill.

**S4. Overview: in-page nav + put the score evidence next to the score.**
Overview is the longest single-scroll page and the only one with neither
pills nor a TOC — `section_toc` was built for exactly this (components.py:470)
and is used once in the whole app (`app/ui/pages/security.py:113`). Add a
TOC strip (Economics / Risk / Actions / Monthly / Trend / Exports) with
anchors on the existing headers. Separately, the Platform-score KPI's help
says "every deduction is itemized below" (`overview.py:537-544`) but the
deductions expander renders ~250 lines later, below the spend trend
(`820-839`) — move it directly under the account KPI row.

**S5. One meta-line per panel.** ~265 `st.caption` sites across `app/ui`;
panels routinely end with 2-4 stacked caption lines (takeaway + source +
row-count + a rec-note — e.g. the spend-trend block, `overview.py:794-807`).
Keep the content, merge the plumbing: takeaway stays its own line (it is
signal), then ONE muted meta-line joining source · fetched · rows · window
(`result_caption` already joins with "·" — extend it to accept the size/sort
bits `_render_table` currently prints separately).

**S6. Cost "Spend & Attribution" should use the same inner-pill pattern as
Optimization.** It stacks Spend + Attribution + a toggle-gated Storage +
Unmapped with dividers (`cost.py:106-140`) while its sibling section already
solved this with `nested_sections` (`cost_parts/optimize.py:225`). Pills also
keep the perf intent for free: only the picked sub-section renders, so the
"load storage detail" toggle can retire.

**S7. KPI-card chip diet (owner taste).** Cards can carry freshness +
method + scope chips + '?' + delta + sub-line + sparkline
(components.py:302-330); on a 4-across row the title line wraps and the
chips compete with the label. Proposal: keep the freshness chip (honesty
rule 8), collapse method+scope into one muted chip ("billed · acct"), full
text stays in the '?' tooltip. rec13's three-token separation was
deliberate — this keeps the information, shrinks the chrome; decline is fine.

## Suggested sequencing

1. **Round 1 (color):** step-0 tokenization of residual literals, then the
   chosen palette + de-slop list. Lockstep: theme.py + palette.py +
   config.toml + `test_palette_drift.py` (+ `_SEVERITY_HUES` only if
   severities ever change) + stable-palette test.
2. **Round 2 (sections):** S1-S4.
3. **Round 3 (polish):** S5-S7, each individually declinable.

Each round is app-only (no migrations), ends gates-green with an
APP_VERSION bump + CHANGELOG entry per house rules. This document is
docs-only and does not bump the version.
